# v0.0.0 specification

## Outcome and platforms

A small usable desktop drawing editor: create/open an image, draw using layers
and shapes, correct it with undo, and save/reopen without losing data.
Windows, macOS, and Ubuntu are release targets. iOS compilation/input feasibility
is an early architecture gate; a usable touch interface is deferred to 0.5.0.

## Required features

- New transparent canvas, PNG import/export, versioned layered project save/open.
- Canvas zoom/pan, checkerboard, dimensions, primary/secondary RGBA colors.
- Brush, eraser, eyedropper; one undo action per completed stroke. If committing
  a stroke fails, the stroke is discarded and the document is unchanged
  (Paint.NET parity).
- Rectangle, rounded rectangle, ellipse, line. Outline/fill/both where applicable,
  stroke width, primary/secondary color assignment, constrained proportions.
- Layers: add/delete/rename/reorder, visibility, opacity; normal source-over blend.
- Undo/redo for every document mutation. New document mutations clear redo.
- Tool palette, tool settings, layers panel, file/edit shortcuts, dirty marker,
  unsaved-change prompts, safe saves and readable error messages.

Selections, text, fill bucket, effects, plugins, JPEG, advanced blend modes,
persistent vector objects, and touch-first UI are excluded.

## Shape interaction contract

1. Pointer-down anchors a shape; dragging previews it without changing pixels.
2. Pointer-up leaves it active with adjustment handles. Position, dimensions,
   rotation, fill, outline, colors, and stroke width remain adjustable.
3. Shift constrains rectangle/ellipse proportions and line angles; exact angle
   increments and handle hit areas must be finalized with the UI specification.
4. Enter or Escape commits the active shape as one history action, matching
   Paint.NET (owner decision 2026-11-12). Discarding a preview is an explicit
   Cancel command or undo. A transparent/off-canvas no-op creates no entry.
5. Starting another shape, changing active layer, undo, and save first commit the
   current shape. Undo then undoes that commit. Redo is disabled while a shape is
   active. Moving, panning, zooming, color selection and eyedropper sampling
   preserve the editable shape; returning to Rectangle preserves it too.
   Dragging inside the active rectangle moves it; handles take precedence.
6. Saving commits before serialization. If writing fails, keep the document dirty
   and preserve the committed edit in history. Saving never discards work.
7. Committed shapes are raster pixels, including after reopening. They are not
   retained as independently editable objects.

The initial engine slice implemented axis-aligned rectangle/ellipse fill,
outline/both, adjustment by replacement, preview, commit/cancel, layers and
history. The desktop spike now adds rectangle corner/edge handles, rotation,
Shift square creation and corner-resize aspect locking, canvas-scoped shortcuts
and tested UI event routing. Line, rounded rectangle, remaining constraints and
the complete style interface remain backlog items.

## Color Picker and Screen Picker

Two separate sources, both writing the selected workspace color slot (Primary
or Secondary, see Workspace colors). Neither adds a history entry.

**Color Picker tool (canvas, Paint.NET parity)** is the controller's
`Tool::Eyedropper`.

- Source: the image composite. Visible layers only, each at its layer opacity,
  blended source-over in encoded RGBA8, including the editable shape preview as
  it was at pointer-down. That preview is frozen for the whole drag, so a
  sample that recolors the preview does not feed back into the same drag.
- Result: straight RGBA with alpha preserved; transparent pixels give
  (0,0,0,0).
- Position: the pixel at `floor` of the document coordinate, after viewport
  pan/zoom. Points outside the canvas are ignored (colors unchanged), on
  pointer-down and while dragging.
- The editable shape is preserved; sampling recolors it like any slot edit.
- Tests: `crates/hoshi-controller/tests/eyedropper.rs` (hidden layer excluded,
  50% opacity blended, alpha preserved, Secondary slot, outside ignored,
  shape preview, history unchanged) and the eyedropper tests in
  `crates/hoshi-controller/tests/color.rs`.
- Tracked gaps versus Paint.NET 5.2 options, not yet implemented: sampling the
  current layer versus the image (currently always the image), sample size
  (currently a single pixel), and the "after click" tool switch (currently the
  tool stays selected).

**Screen Picker (OS screen, Hoshi extra)** is a Colors-panel action, not a
tool.

- Source: the screen pixel under the pointer anywhere on screen, via the
  platform pickers in `spikes/desktop-canvas/src/screen_pick.rs`.
- Result: RGB rounded to RGBA8 and always opaque (alpha 255); invalid or
  non-finite components are rejected.
- Cancel or failure leaves both colors unchanged; failure shows an error.
- Tests: `screen_rgb_is_rounded_and_opaque` and
  `invalid_screen_components_are_rejected` (`screen_pick.rs`),
  `screen_result_recolors_preview_and_cancel_or_failure_preserves_it`
  (`spikes/desktop-canvas/src/colors.rs`).

## Release acceptance scenario

1. Create a transparent canvas; paint on the first layer.
2. Add a layer; draw a filled ellipse and outlined rectangle.
3. Move/resize/rotate a shape before committing; cancel a second shape.
4. Change layer order/opacity/visibility, rename a layer, then undo/redo edits.
5. Save, close, reopen; verify pixels, dimensions, names, order, and properties.
6. Export PNG; decode it and compare with the composited canvas.
7. Verify unsaved-change prompts and failed-save recovery.

Run on all desktop targets. Automated core tests cover geometry, alpha,
compositing, boundaries, lifecycle, history and eventually file round trips.
Manual/input automation checks cover shortcuts, handles and pointer capture.

## Performance and release gates

Before GUI implementation, record named reference machines for each desktop OS.
Proposed budgets (ratify on those machines): smooth 60 Hz canvas navigation on
a 2048×2048 document with 8 layers, <=50 ms pointer-to-preview p95, <=100 ms
simple action undo p95, <=1 GiB working memory for that document. Measure release
builds and report hardware, workload, sample count, p50/p95 and peak memory.
These are targets, not current measured capabilities.

No release with known data loss, unexplained required-check failures, or missing
desktop acceptance evidence. UI accessibility and the iOS feasibility gate must
have documented outcomes. v0.0.0 may explicitly limit document dimensions based
on measured memory use; reject oversized files safely before allocation.

## Workspace colors

Primary and Secondary colors belong to the workspace rather than to a shape style.
The selected slot controls color editing and screen sampling, independent of the
active tool or shape mode. Fill-only and outline-only shapes use Primary; Both
uses Primary for outline and Secondary for fill. Slots default to opaque black
and white, support alpha, and can be swapped (X) or reset (D). Color settings are
not document history; active preview updates commit as part of the shape's single
history entry. Already committed pixels never follow later slot edits.

Per-slot Original comparisons last for one Colors-panel session, including slot
switches, swaps, resets and docking. Restore affects the currently selected slot.
Right-button reversed color painting remains future work because right-drag is
currently a canvas navigation gesture. Persistent saved palettes remain backlog.
