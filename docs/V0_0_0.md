# v0.0.0 specification

## Outcome and platforms

A small usable desktop drawing editor: create/open an image, draw using layers
and shapes, correct it with undo, and save/reopen without losing data.
Windows, macOS, and Ubuntu are release targets. iOS compilation/input feasibility
is an early architecture gate; a usable touch interface is deferred to 0.5.0.

## Required features

- New transparent canvas, PNG import/export, versioned layered project save/open.
- Canvas zoom/pan, checkerboard, dimensions, primary/secondary RGBA colors.
- Brush, eraser, eyedropper; one undo action per completed stroke.
- Rectangle, rounded rectangle, ellipse, line. Outline/fill/both where applicable,
  stroke width, primary/secondary color assignment, constrained proportions.
- Layers: add/delete/rename/reorder, visibility, opacity; normal source-over blend.
- Undo/redo for every document mutation. New document mutations clear redo.
- Tool palette, tool settings, layers panel, file/edit shortcuts, dirty marker,
  unsaved-change prompts, safe saves and readable error messages.

Selections, text, fill bucket, effects, plugins, JPEG, advanced blend modes,
persistent vector objects, and touch-first UI are excluded.

## Shape interaction contract

1. Pointer-down anchors a shape; dragging previews it without changing pixels.
2. Pointer-up leaves it active with adjustment handles. Position, dimensions,
   rotation, fill, outline, colors, and stroke width remain adjustable.
3. Shift constrains rectangle/ellipse proportions and line angles; exact angle
   increments and handle hit areas must be finalized with the UI specification.
4. Enter commits the active shape as one history action. Escape cancels without
   changing pixels or history. A transparent/off-canvas no-op creates no entry.
5. Switching tools, starting another shape, changing active layer, undo, and save
   first commit the current shape. Undo then undoes that commit. Redo is disabled
   while a shape is active. Panning/zooming leave the shape active.
6. Saving commits before serialization. If writing fails, keep the document dirty
   and preserve the committed edit in history. Saving never discards work.
7. Committed shapes are raster pixels, including after reopening. They are not
   retained as independently editable objects.

The initial engine slice implements axis-aligned rectangle/ellipse fill,
outline/both, adjustment by replacement, preview, commit/cancel, layers and
history. Handles, rotation, line, rounded rectangle, shortcuts, and UI event
routing remain explicit backlog items.

## Release acceptance scenario

1. Create a transparent canvas; paint on the first layer.
2. Add a layer; draw a filled ellipse and outlined rectangle.
3. Move/resize/rotate a shape before committing; cancel a second shape.
4. Change layer order/opacity/visibility, rename a layer, then undo/redo edits.
5. Save, close, reopen; verify pixels, dimensions, names, order, and properties.
6. Export PNG; decode it and compare with the composited canvas.
7. Verify unsaved-change prompts and failed-save recovery.

Run on all desktop targets. Automated core tests cover geometry, alpha,
compositing, boundaries, lifecycle, history and eventually file round trips.
Manual/input automation checks cover shortcuts, handles and pointer capture.

## Performance and release gates

Before GUI implementation, record named reference machines for each desktop OS.
Proposed budgets (ratify on those machines): smooth 60 Hz canvas navigation on
a 2048×2048 document with 8 layers, <=50 ms pointer-to-preview p95, <=100 ms
simple action undo p95, <=1 GiB working memory for that document. Measure release
builds and report hardware, workload, sample count, p50/p95 and peak memory.
These are targets, not current measured capabilities.

No release with known data loss, unexplained required-check failures, or missing
desktop acceptance evidence. UI accessibility and the iOS feasibility gate must
have documented outcomes. v0.0.0 may explicitly limit document dimensions based
on measured memory use; reject oversized files safely before allocation.
